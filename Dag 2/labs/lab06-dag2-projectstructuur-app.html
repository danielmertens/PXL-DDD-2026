Wat is er al, wat niet?

De starter bevat enkel de domeinlaag: de AlbumAggregate met Create, ChangeDescription, ChangeBackgroundImage, ChangePublicationYear en Like, de value objects en de events. Je krijgt wel al een stub AlbumService (met IAlbumService) die in Program.cs geregistreerd is. De twee endpoints in Program.cs doen nog niets: die koppel je zelf.

Herhaling: onion architecture

  • Domain logica staat centraal
  • Afhankelijkheid is naar binnen toe; het domein kent de infrastructuur niet
  • Alles is losgekoppeld via interfaces, beschreven in de application- en domain layer

Voorgestelde structuur

Per aggregate één map, met daarin Domain en Application:

HarmonyTunes.Catalogue/
└── Album/
    ├── Domain/              AlbumAggregate, AlbumState, events, value objects
    └── Application/
        ├── Interfaces/      IAlbumService, IAlbumRepository
        └── AlbumService.cs
HarmonyTunes.Ports/
├── Catalogue/Adapters/      implementaties van je interfaces (InMemoryAlbumRepository)
└── Program.cs               composition root: DI, endpoints, dto's

De namespace volgt de map, bv. HarmonyTunes.Ports.Catalogue.Adapters.Database.Album.

De application service

Een application service is use case oriented, bevat geen domeinlogica en beschrijft een proces. Typisch:

  1. Validatie van de input
  2. Ophalen van de aggregate (via de repository-interface)
  3. Uitvoeren van het domain command op de aggregate (Create, ChangeDescription)
  4. Opslaan van de aggregate
  5. Notificaties verzenden van belangrijke events (pas in oefening 8)

Begin met de poort: een interface in Application. De implementatie komt later in Ports.

// HarmonyTunes.Catalogue/Album/Application/Interfaces/IAlbumRepository.cs
public interface IAlbumRepository
{
    AlbumReference GetNextIdentity();
    void Add(AlbumAggregate album);
    void Update(AlbumAggregate album);
    Task<AlbumAggregate> Fetch(AlbumReference id);
    Task Commit();
}

De service krijgt de repository via de constructor:

public class AlbumService : IAlbumService
{
    private readonly IAlbumRepository _albumRepository;

    public AlbumService(IAlbumRepository albumRepository)
    {
        _albumRepository = albumRepository;
    }

    // CreateAlbum en ChangeDescription: vul de TODO's uit de stub in
}

Optioneel: een generieke basisklasse ApplicationService<TAggregate, TState, TId> met Add en Update haalt de herhaling uit je services zodra je meer dan één aggregate hebt.

Een in-memory repository

Tot oefening 7 bewaar je de aggregates in het geheugen. Bewaar de state en de version, niet de aggregate zelf:

// HarmonyTunes.Ports/Catalogue/Adapters/Database/Album/InMemoryAlbumRepository.cs
public class InMemoryAlbumRepository : IAlbumRepository
{
    private readonly Dictionary<Guid, (AlbumState State, int Version)> _albums = new();

    // Fetch: zoek state en version op en bouw de aggregate terug op
    //        met new AlbumAggregate(state, id, version); die constructor bestaat al
}
// Program.cs: singleton, anders is je dictionary bij elke request leeg
builder.Services.AddSingleton<IAlbumRepository, InMemoryAlbumRepository>();
builder.Services.AddScoped<IAlbumService, AlbumService>();

De api als buitenste laag

  • De dto's (CreateAlbumDto, ChangeAlbumDescriptionDto) blijven in Ports; het domein kent ze niet
  • In het endpoint zet je de dto om naar domeintypes (AlbumName, AlbumDescription) en roep je IAlbumService aan
  • Geef een verwijzing terug (de AlbumReference) zodat de client de aggregate kan wijzigen
  • Ontwikkelmodus: test via Swagger

Een minimal api-endpoint krijgt geregistreerde services gewoon als parameter:

app.MapPost("/api/albums/create", async (CreateAlbumDto dto, IAlbumService albumService) =>
{
    // dto → AlbumName, de service aanroepen, de Key van de AlbumReference teruggeven
});

Controleer

Alle projectreferenties wijzen naar binnen: Ports → Catalogue → Domain.Core, nooit omgekeerd. Er zit geen domeinlogica in AlbumService of in de endpoints.

je via de api/console een album kan aanmaken en de beschrijving kan wijzigen, met het domein als enige drager van domeinlogica.
