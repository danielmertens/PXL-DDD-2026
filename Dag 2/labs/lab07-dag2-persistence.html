Kies je aanpak

State stored

Je bewaart de huidige state van de aggregate. Voeg een id en een version toe; de version dient voor optimistic concurrency. Houd je domain state vrij van persistentiedetails.

Event sourced

Je bewaart enkel de events en bouwt de aggregate bij elke fetch op door ze opnieuw af te spelen (replay). Zorg dat je events backwards compatible blijven.

Beide aanpakken implementeren dezelfde IAlbumRepository uit oefening 6.

De repository

Implementeer de repository-interface uit je application layer in Ports (bv. AlbumRepository). De service blijft ongewijzigd:

  • Add, Update, Fetch en Commit; de service roept Commit pas op nadat het domain command uitgevoerd is
  • GetNextIdentity genereert de nieuwe AlbumReference
  • Update doet niets als de aggregate geen events heeft

State stored: id en version buiten je state

Met shadow properties krijgt de tabel een id- en een version-kolom zonder dat AlbumState ze kent:

// HarmonyTunes.Ports/Catalogue/Adapters/Database/Album/AlbumConfiguration.cs
public class AlbumConfiguration : IEntityTypeConfiguration<AlbumState>
{
    public void Configure(EntityTypeBuilder<AlbumState> builder)
    {
        builder.Property<Guid>("AlbumId").ValueGeneratedNever();
        builder.HasKey("AlbumId");
        builder.Property<int>("Version").IsConcurrencyToken();

        // value object ↔ kolom; doe hetzelfde voor Description,
        // BackgroundImageUrl, PublicationYear en Likes
        builder.Property(p => p.Name)
            .HasConversion(name => name.Value, text => new AlbumName(text));
    }
}

Status is een enum: die mapt EF zelf. In de repository lees en schrijf je de shadow properties zo:

_context.Entry(state).Property("AlbumId").CurrentValue = album.Id.Key;
var version = _context.Entry(state).Property<int>("Version").CurrentValue;

_context.Albums.Where(a => EF.Property<Guid>(a, "AlbumId") == id.Key)

Bij Fetch bouw je de aggregate op met new AlbumAggregate(state, id, version); die constructor bestaat al.

Event sourced: een tabel met events

Eén rij per event; een unieke index op stream en volgnummer is je optimistic concurrency:

public class EventEntity
{
    public Guid Id { get; set; }
    public Guid AggregateId { get; set; }
    public int Version { get; set; }                          // volgnummer in de stream
    public string MessageType { get; set; } = string.Empty;   // evt.GetType().Name
    public string EventData { get; set; } = string.Empty;     // het event als json
}

// in de configuratie
builder.HasIndex(e => new { e.AggregateId, e.Version }).IsUnique();
// opslaan: geef het runtime-type mee, anders serialiseer je enkel IDomainEvent
row.EventData = JsonSerializer.Serialize(evt, evt.GetType());

// inlezen: het type vind je terug via MessageType
// Type.GetType verwacht "<namespace>.<klasse>, <assembly>"
var eventType = Type.GetType(
    $"HarmonyTunes.Catalogue.Album.Domain.Events.{row.MessageType}, HarmonyTunes.Catalogue")!;
var domainEvent = (IDomainEvent)JsonSerializer.Deserialize(row.EventData, eventType)!;

Voor de replay heeft AggregateRoot een extra constructor nodig, en AlbumAggregate een die ernaar doorgeeft:

// HarmonyTunes.Domain.Core/AggregateRoot.cs
protected AggregateRoot(TId id, IEnumerable<IDomainEvent> events)
{
    // nieuwe state, elk event toepassen met Mutate, Version = aantal events
}

Let op: System.Text.Json leest een value object in via zijn constructor en koppelt de parameters op naam aan de properties. Daarom heet de parameter in de starter value, net als de property Value: public AlbumName(string value). Doe dat ook in je eigen value objects, anders faalt Fetch met een InvalidOperationException.
