Opdracht

  1. Implementeer een side effect in je code
    • Verstuur een command/notification
    • Behandel het event
    • Verstuur via de outbox: aggregate en bericht in één transactie

Hoe past messaging in je architectuur?

  • De application layer kent enkel een interface, bv. IMessagePublisher, en een INotification
  • De implementatie (MassTransit op RabbitMQ) zit in Ports, net als de handler (consumer) en de outbox
  • De service publiceert vóór de commit: via de outbox bewaart die commit aggregate én bericht in één transactie

Stappen

  1. Definieer een notification, bv. AlbumUpdatedNotification met de AlbumReference
  2. Publiceer ze in AlbumService vóór Commit, zodat aggregate en bericht in dezelfde transactie zitten
  3. Schrijf in Ports een consumer die de notification afhandelt (bv. loggen of een aanroep naar een service)
  4. Registreer de bus in DI en geef de consumers mee
  5. Zet de outbox aan: package MassTransit.EntityFrameworkCore, AddEntityFrameworkOutbox<CatalogueContext> met UsePostgres() en UseBusOutbox(), de outbox-entities in OnModelCreating en een migratie

RabbitMQ opzetten

Start RabbitMQ met het commando uit docker commands.txt; het beheerscherm staat op localhost:15672 (guest / guest, enkel voor development).

De versies staan centraal in Directory.Packages.props; in het project komt enkel de referentie, zonder versie:

<!-- HarmonyTunes.Ports.csproj -->
<PackageReference Include="MassTransit.RabbitMQ" />
<PackageReference Include="MassTransit.EntityFrameworkCore" />

De poort in de application layer

// HarmonyTunes.Catalogue/Shared/Application/Interfaces
public interface INotification
{
}

public interface IMessagePublisher
{
    Task Publish<T>(T notification)
        where T : INotification;
}

De bus registreren

// Program.cs
builder.Services.AddMassTransit(configure =>
{
    configure.AddEntityFrameworkOutbox<CatalogueContext>(outbox =>
    {
        outbox.UsePostgres();      // lock-SQL voor Postgres (default: SQL Server)
        outbox.UseBusOutbox();     // IPublishEndpoint schrijft naar de outbox
        outbox.QueryDelay = TimeSpan.FromSeconds(1);
    });

    configure.AddConsumers(typeof(Program).Assembly);   // alle IConsumer<T> in Ports

    configure.UsingRabbitMq((context, rabbit) =>
    {
        rabbit.Host("localhost", "/", host =>
        {
            host.Username("guest");
            host.Password("guest");
        });

        rabbit.ReceiveEndpoint("HarmonyTunes.Catalogue.In", endpoint =>
        {
            endpoint.UseMessageRetry(retry => retry.Interval(3, TimeSpan.FromMilliseconds(200)));
            endpoint.ConfigureConsumers(context);
        });
    });
});

// jouw implementatie van IMessagePublisher, op de scoped IPublishEndpoint
builder.Services.AddScoped<IMessagePublisher, MessagePublisher>();

De outbox-tabellen komen in je eigen CatalogueContext, gevolgd door een migratie:

// CatalogueContext.OnModelCreating
modelBuilder.AddInboxStateEntity();

De consumer

AddConsumers vindt elke klasse die IConsumer<T> implementeert:

// HarmonyTunes.Ports/Catalogue/Adapters/Messaging/Consumers/AlbumUpdatedNotificationHandler.cs
public class AlbumUpdatedNotificationHandler : IConsumer<AlbumUpdatedNotification>
{
    public Task Consume(ConsumeContext<AlbumUpdatedNotification> context)
    {
        // context.Message is je notification; begin met loggen
        throw new NotImplementedException();
    }
}

Let op

  • Asynchrone bezorging kan duplicaten geven: maak je handler idempotent
  • Asynchroon is niet transactioneel; voor een proces over meerdere stappen heb je een saga met compensatiestappen nodig
  • Enkel de scoped IPublishEndpoint gaat via de outbox; IBus.Publish niet
  • Publish zonder commit faalt stil: het bericht komt nooit in OutboxMessage

Controleer

Maak of update een album via de api en zie in de logs of in RabbitMQ dat het bericht aankomt en verwerkt wordt. Stop daarna RabbitMQ (docker stop harmonytunes-rabbitmq) en maak een album aan: het bericht wacht in "Catalogue"."OutboxMessage" en wordt verwerkt zodra RabbitMQ terug draait.

Klaar wanneer

bij het opslaan van je aggregate een bericht via de outbox naar buiten gaat en een handler dat effectief ontvangt en verwerkt, ook als RabbitMQ even plat lag.
